Big new feature. We need to do time shit. Controlling two characters simultaneously while dealing with time limits doesn't really work well gameplaywise unless it's turn based, believe it or not. Moving characters in alternation sucks, so you want to be able to move one independently for a while then only move the second to follow once they need to cross paths/interact. So we're going to do that by, when you wanna move the second player, rewind to the last time they moved, which will rewind the first player's actions, then as the second player moves, the first one's actions replay in parallel. This means the actions later moving characters take can interfere with the actions of the first character, in some cases invalidating them, but we can detect that. So:
	there has to be a time dial that can turn time forwards and backwards. Move the clock to the lower left side of the map, and make it bigger. When the player turns it, it turns time back and forth.
	time needs to advance only when the player does things (or if playing, during ticks), such as walking, or riding a train, or turning the time dial forward
	we need to be able to record action histories so that we can replay them after rewinding
		scheduled actions can become invalid, for instance if a player is about to take an item from a container that doesn't have anything in it, or move on to a train that's not at this station, which stops that player's action history from replaying any further, and shows a minor alert message.
	make sure that nothing is framerate dependent, so, there's a strict ordering of events to come that's knowable in advance. If a player is moving towards a node, their arrival time and trajectory is known, anything that acts on space knows whether they will be within range at the time it will fire.
	actions/events must be reversible, which is to say, if they destroy state, the action must keep the state it destroyed, so that it can restore it if reversed.
